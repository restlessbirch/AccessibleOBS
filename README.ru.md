# Accessible OBS

Доступная веб-панель и удалённое управление OBS Studio для Windows.

English version: [README.md](README.md)

## Зачем это нужно

OBS Studio не работает с экранным диктором. Его окно — поверхность отрисовки:
у большей части того, что там важно, просто нет дерева доступности. Незрячий
стример не может проверить, идёт ли звук в микрофон, не чёрный ли экран у
зрителей и доходит ли эфир вообще.

Обычный ответ на это — «попроси зрячего сесть рядом». На живом эфире так не
получится, а если человек в другом городе, то не получится совсем.

Accessible OBS заменяет окно OBS на то, что диктор умеет читать, и позволяет
управлять с другого компьютера, а не с того, где идёт эфир.

## Для кого

**Незрячий стример на своём компьютере.** Локальный режим даёт панель с
клавиатурным управлением для OBS на этой же машине. Ни сети, ни pairing-кода.

**Оператор, который ведёт чужой эфир.** Удалённый режим: панель у оператора,
OBS у стримера, между ними Tailscale. Человек перед камерой после однократной
настройки не делает ничего — Tailscale, OBS и агент поднимаются сами при входе
в Windows.

## Как это устроено

На компьютере стримера работают игра, OBS Studio и небольшой фоновый агент.
Агент связан с OBS по obs-websocket на петлевом интерфейсе и отдаёт веб-панель.

На компьютере оператора — только браузер с экранным диктором. До агента он
дотягивается через Tailscale: это шифрованная частная сеть между двумя
машинами, наружу в интернет ничего не публикуется.

```
        Компьютер стримера
   ┌─────────────────────────┐
   │  Игра                   │
   │  OBS Studio             │
   │  Агент Accessible OBS   │
   └────────────┬────────────┘
                │
                │  Tailscale
                │
   ┌────────────▼────────────┐
   │  Удалённый оператор     │
   │  Браузер + экранный     │
   │  диктор                 │
   └─────────────────────────┘
```

## Два режима интерфейса

Режим выбирается на начальной странице и решает, что панель показывает и что
произносит вслух.

**Доступный режим**, он же по умолчанию. Чат, донаты и тревоги об эфире
объявляются живыми областями, то есть диктор произносит их сразу. Вывод на
второй монитор скрыт: окно проектора OBS — поверхность отрисовки без дерева
доступности, и это была бы кнопка, открывающая то, что незрячий не прочитает и
потом не найдёт, чтобы закрыть.

**Обычный режим**, для зрячего оператора. Чат и донаты можно вывести на второй
монитор через проектор OBS. Вслух не читается ничего.

## С чего начать

Скачайте или соберите архив релиза.

Распакуйте его в постоянную папку.

Запустите `AccessibleOBS.exe`.

Откроется небольшое доступное меню в браузере, на рабочем столе появится ярлык.
Дальше выберите одно из трёх.

`Актёр` — подготовить этот компьютер к эфиру. Поставит OBS и Tailscale, если их
нет, включит obs-websocket, пропишет агент в автозапуск и покажет pairing-код.

`Оператор` — открыть панель удалённого управления и ввести pairing-код.

`Локальный доступный режим` — открыть панель для OBS на этом же компьютере,
только на `127.0.0.1`, без Tailscale и без pairing-кода.

## Что умеет панель

Начинать и останавливать эфир, запись, буфер повтора, виртуальную камеру и
Studio Mode.

Переключать сцены, добавлять и удалять источники, менять видимость и
настройки источников OBS.

Показывать уровни звука, чтобы отличить живой микрофон от заглушенного, а
заглушенный — от выдернутого из гнезда.

Читать чат Twitch обычным списком элементов страницы, а не чужим встроенным
виджетом: диктор объявляет новые сообщения, а не прячет их во фрейме.

Показывать последние донаты и настраивать DonationAlerts внутри OBS так, чтобы
алерты были и видны, и слышны в эфире.

Менять название канала Twitch, категорию, язык и ставить метки.

Брать кадр эфира по требованию — проверить чёрный экран, не занимая канал
стримера постоянным видеопотоком.

Проверять готовность к эфиру перед стартом.

Складывать ошибки браузера в тот же файл журнала, что и свои, и отдавать сводку
для разбора поломки.

## Проверка готовности

Проверка отвечает на вопрос «можно ли выходить в эфир», а не «отвечает ли OBS».

Связь с OBS и заданный ключ трансляции.

Есть ли что-нибудь в текущей сцене, с обходом вложенных сцен и групп.

Действительно ли активны видимые источники, через `GetSourceActive`.

Назначен ли микрофон, не заглушен ли он и идёт ли по нему звук.

Захват системного звука, из-за которого в эфир уехала бы речь вашего же
экранного диктора.

Свободное место на диске при записи.

Связь с Twitch и состояние оверлея донатов.

Неизвестный результат показывается как неизвестный, а не как зелёный. Проверка,
которая не смогла выполниться, — это не пройденная проверка.

## Второй экран стримера

Панель умеет открыть на компьютере стримера страницу только для просмотра — с
чатом и донатами, либо отдельно с чатом, либо отдельно с донатами.

В обычном режиме панель может вывести эту страницу на выбранный физический
монитор через проектор OBS, чтобы никому не пришлось таскать окно между
экранами.

Ссылку виджета DonationAlerts страница не раскрывает — это секрет. Её данные
доступны без сессии панели только с этой же машины и только при доверенном
происхождении запроса.

## Twitch и DonationAlerts

Twitch настраивается в панели: сохраните Client ID, подключитесь через Device
Code OAuth — дальше панель управляет каналом. Нужное право —
`channel:manage:broadcast`.

Чат читается анонимно и токена не требует вовсе, поэтому работает ещё до OAuth.

Для алертов в эфире вставьте в панель официальную ссылку Alerts Widget с сайта
DonationAlerts. Accessible OBS создаст и починит сцену оверлея, источник-браузер,
его положение поверх остальных источников в каждой сцене и маршрутизацию звука,
без которой зрители алерты не услышат. После этого перечитает OBS и убедится —
а не отчитается об успехе просто потому, что команды отправлены.

Для списка донатов в панели подключите OAuth DonationAlerts.

## Безопасность

obs-websocket остаётся на `127.0.0.1`, с сетью разговаривает только агент.

Удалённый доступ идёт через Tailscale с сессией по pairing-коду.

Локальный режим слушает только петлевой интерфейс.

Секреты лежат под Windows DPAPI в `config\secrets\*.dpapi` и не попадают ни в
ответы API, ни в журнал.

Прямой доступ к протоколу OBS ограничен списком запросов только на чтение.

Origin и Host проверяются, чтобы страница чужого сайта не управляла панелью
через браузер самого оператора.

Прочитайте [SECURITY.md](SECURITY.md), прежде чем вести на этом настоящий эфир.

## Сборка

Нужны Windows 10 или 11, Rust версии не ниже указанной в `rust-version` файла
`Cargo.toml`, PowerShell и OBS Studio для проверки на живой системе.

Собрать архив релиза:

```powershell
BUILD.bat
```

## Чего пока нет

Релиз — это архив с одним очевидным запускающим файлом внутри, а не единый
самораспаковывающийся установщик.

Работа на двух машинах, установка с нуля, автозапуск после перезагрузки и
Twitch с DonationAlerts на живых учётных записях сквозной проверки не проходили.
Всё остальное, описанное здесь, проверено на работающем OBS Studio.

Разграничения прав между операторами нет: вошедший оператор управляет всей
панелью.

Сцены и источники, которые программа создаёт в OBS, до сих пор носят префикс
`RSC_` от прежнего названия. Чтобы переименовать их, нужен шаг миграции — иначе
в уже настроенном OBS останутся висеть осиротевшие сцены.
